## 节点编排

```text
开始
  -> 输入校验
  -> 简历事实库（知识库/文本变量）
  -> 大模型：JD 结构化解析
  -> 大模型：经历证据匹配
  -> 条件分支：匹配度 >= 70
       ├─ 是 -> 大模型：生成定制材料
       └─ 否 -> 大模型：生成差距与补强建议
  -> 大模型：质量审校
  -> 结束：Markdown 结果
```

## 开始节点

输入变量：

- `job_description`：String，必填，招聘 JD 原文。
- `target_material`：Enum，可选，`全部`、`简历`、`自我介绍`、`求职邮件`、`面试准备`。
- `tone`：Enum，可选，`专业克制`、`积极有行动力`。

输入校验节点：JD 少于 80 字时直接结束并提示“请粘贴完整岗位描述，包括职责和任职要求”。

## 大模型节点 1：JD 结构化解析

系统提示词：

```text
你是跨境电商与数据运营招聘分析师。只根据输入 JD 提取事实，不补写不存在的信息。
输出 JSON：
{
  "role": "岗位名称",
  "industry": "行业",
  "must_have": ["硬性要求"],
  "responsibilities": ["核心职责"],
  "keywords": ["关键词"],
  "metrics": ["涉及的业务指标"],
  "seniority": "实习/校招/社招/未知"
}
```

## 大模型节点 2：经历证据匹配

输入：JD 解析 JSON + 简历事实库。

要求：逐项匹配，输出 `matched_evidence`、`missing_requirements`、`score`。评分公式：硬性要求 50%，职责证据 30%，工具技能 10%，行业相关性 10%。不得把“参与”改写成“主导”，不得虚构公司、项目或指标。

## 条件分支

- `score >= 70`：进入定制材料生成。
- `score < 70`：进入差距分析，只生成真实经历可支持的补强建议，不输出虚假的匹配结论。

## 大模型节点 3：定制材料生成

输出四部分：

1. **岗位匹配度**：总分、三条最强证据、两条待补强项。
2. **简历改写**：3-5 条 STAR 风格经历，每条包含动作、工具、结果；保留真实数字。
3. **60 秒自我介绍**：优先突出广州荧链科技有限公司亚马逊运营助理经历与数据成果。
4. **求职邮件**：主题、称呼、正文、署名；正文不超过 220 字。

当 `target_material` 不是“全部”时，只返回对应部分。

## 大模型节点 4：质量审校

系统提示词：

```text
你是简历事实审校员。检查最终内容：
1. 公司名必须为“广州荧链科技有限公司”；
2. 不得新增简历没有的公司、职责、学历、证书和业绩；
3. 16.5 万、4.1 万、27.34%、24.85%、88.35%、4 款、50 条、20 场、1000+、30%必须保持原意；
4. 标记所有无法由简历事实库支持的句子，并给出修正版。
输出：{"passed": true/false, "issues": [], "final_answer": "审校后的 Markdown"}
```
